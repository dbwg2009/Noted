**For new phases / significant features:**
1. Read the relevant design doc (`V2_DESIGN.md` etc.) and summarise the scope in plain English
2. Ask the user if they want to change anything about the scope
3. Ask all clarifying questions upfront in a single numbered list so the user can reply "1. yes 2. no 3. ..." style
4. Wait for explicit "go ahead" (or equivalent) before writing a single line of code — finishing Q&A is not enough

**For small changes (bug fixes, minor UI tweaks):**
- No planning round needed — just get on with it

**Why:** User wants to stay in control of scope before any work starts, but doesn't want unnecessary overhead for small tasks.

**How to apply:**
- Never start building after Q&A alone — wait for the explicit go-ahead
- Keep the scope summary concise (3-5 bullet points max)
- All questions in one message, numbered, no follow-up question rounds
